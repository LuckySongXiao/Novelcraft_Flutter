## 本版变更（承接手机端真机实测反馈）

### 1. BUG 1：串行写书输出污染

用户手机截图暴露的泄漏**全部在正文之前**，三种真实形态：自我介绍/处理说明前缀与正文同段、
「修订稿」抬头 + 星号字段与正文同行、整行章节元信息区块。

- 新增 `AIOutputSanitizer.stripMetaPreambles()`，接入 `extractCleanOutput` 与
  `MultiAgentBookGenerationService._cleanFinalChapter` 两处。
- 新增**长度安全阀** `_kMaxMetaLineChars = 800`：旧判据「一行塞 ≥2 个元信息小标题就整行丢」
  会被**单行长文**满足，章节正文里恰好出现两个 `【人物】`/`【本章】` 小标题就会**整章被吞**。

### 2. BUG 2：云端 RWKV state 落到客户端本地

物理约束：`rwkv_lightning` **没有 state 导出端点**（`POST/GET /state` 实测 404），
因此唯一可行方案 = 客户端持 `session_id` + 转写本持久化 + 丢会话时经
`/state/chat/completions` 重放重建。

- 会话粒度 = **作用域 × 角色**：规划组 `<书名>::plan`、写作组
  `<项目 id>::chapter::<章 id>`，最终 `<前缀>::<角色>`。
- 台账键加端点身份前缀：`<baseUrl host>::<sessionKey>`（state 在服务端，
  两个端点上的同名 session 是两条不同状态链）。
- 同会话**绝不并发写** → `ledger.runExclusive(key, …)` 在客户端排队。
- 存储键必须做 `:` → `_` 转义（native KVStore 拿 key 当文件名，Windows 禁冒号，
  不过就会**静默写不进去**）。
- 修掉两个真实缺口：
  ① G1K 双模型模式的章节链路 `temporaryWriter` 原先**裸构造**
  （`sessionLedger = null`、`clientStateEnabled = false`），state 完全没用上；
  ② `newSessionId()` 旧实现在 Windows 上紧密循环 200 次**只得到 6 个不同值**
  （`microsecond` 分辨率不足 + 取模易碰），撞 ID 会把两条独立状态链混作一条。
  现为 `nc-<毫秒>-<进程内单调序号 base36>-<随机 4 位>`。
- 新增 `test/rwkv_cloud_state_test.dart`（23 例，此前该模块**零覆盖**）。

### 3. BUG 3：章节审核通过后自动同步设定

审核通过后自动更新人物管理中的角色信息与角色履历，以及世界观各子项的内容信息与状态履历。

### 4. 编排拓扑改造（用户指定）

| 层次 | 编排 | 实现 |
|---|---|---|
| 主线大纲 | 串行 | 规划组 `leader` 单链，一次调用产出全书骨架 |
| 支线大纲（分卷/章节） | 并行 | 9 条规划写手链；`_runPoolIndexed` 让每个并发道**固定绑一条通道** |
| 单章内容 | 串行 | 每章各自一条状态链，段与段严格串行 |
| 全书章节 | 并行 | `lanes = cfg.concurrency`，章间零依赖，同时开工 |

- 章节会话前缀由「项目级」改为 `<projectId>::chapter::<章 id>`：`duo`（默认工艺）
  只有 `leader` 一个角色，项目级共享链会让台账把全书章节排成一条队，
  「N 章并行」退化成**整书严格串行**，`concurrency` 完全失效。
- 支线大纲由「任务序号 % 通道数」改为 **lane → 通道一一绑定**：章节大纲的序号是
  **卷内序号**（每卷从 1 重新数），池宽 9 时第 10 个任务会与在飞的第 1 个任务**撞同一会话**。
- beam 多候选一律走无状态链路（`isolated: true`）：候选是 `Future.wait` 并发的，
  共用 lead 的 state 会①候选互相污染②被台账 `runExclusive` 排成串行白给并发。
  候选数为 1（G1K 双模型快写）时是严格串行，**保留** state。

### 5. 版本号与状态栏

- 版本提升至 `1.0.0+36`（同步 `pubspec.yaml` / `version.txt` / 新增 `lib/core/app_version.dart`）。
- 底部状态栏此前**硬编码** `v1.0.0+23`，现改为引用 `kAppVersionLabel`。

### 6. 打包链路修复（本轮新发现）

- 两个 tools 脚本硬编码的干净源码快照目录名（`Novelcraft_Flutter_source_v1.0.0+35`）
  **早已被改名**为 `novelcraft_1.0.0+35_source`，导致 `sync` 静默跳过
  （它不创建目录）、`package_release.py` 在第 2 步中断。
  现统一改为 `find_clean_snapshot()` **自动探测**。
- `sync()` 原先只遍历快照**已有**条目，工程新增文件**永不入包** ——
  实测漏掉 `lib/ai/rwkv/rwkv_cloud_state.dart`（BUG 2 核心模块）等 3 个文件。
  现按 `NEW_SOURCE_DIRS` 白名单自动补入新增手写文件；
  平台目录只更新不新增，签名密钥/生成物严格排除。

## 构建与发布

使用 Flutter 3.38.5 / Dart 3.10.4。

- Windows：在 ASCII junction `F:\30_Novelcraft_Flutter\novelcraft_en` 下执行
  `flutter build windows --release`，发布整个 `build/windows/x64/runner/Release` 目录。
- Android：先 `subst S: <工程目录>` 再在 `S:\` 下 `flutter build apk --release`
  （中文路径会让 `:app:compileFlutterBuildRelease` 报
  `Cannot invoke "java.io.File.exists()" because "parent" is null`），构建后 `subst S: /D`。
- 正式包文件名：`novelcraft_1.0.0+36_windows_release.zip`、`novelcraft_1.0.0+36_release.apk`。
- 源代码备份含 `pubspec.lock`；不包含签名私钥、`key.properties`、`local.properties`、
  用户数据库、模型权重及构建缓存。复现原签名 APK 需由项目所有者另行配置现有签名材料。
- 最终文件大小、SHA256、签名检查和备份位置记录在工作区根目录的 `发布清单-v1.0.0+36.md`。
- 本次没有安卓真机安装和 Windows 手工交互验收。
