## 二、13B 默认模型的实现要点

`ModelManager` 全局只有一个 `RWKV Cloud` 实例（指向用户在「AI 配置」里启用的端点，默认 7B）。
把选节助手换成 13B **不能**动这个全局实例 —— 否则整书生成、内容复盘等链路会被一起换掉。

解析顺序（任何一步不可用都向后回落，绝不抛异常）：

1. Agent 端点注册表里已有**带凭据**的 `RWKV Cloud::official-13b` → 复用；
2. 用持久化云端档案拼出 13B 端点（**缺凭据时从其它档案补** —— 四个官方端点同属一个
   Cloudflare 区域，Service Token 通用），`configure(probe: true)` 用一次 `/models`
   核实可达后注册进注册表（本次会话复用，不重复探活）；
3. 全局 `RWKV Cloud` 实例本身已指向 `api-13b.rwkvos.com`；
4. 回落：双 Agent 设置（启用双代理时取 mainAgent）→ 默认 provider。

**UI 如实回显**：面板顶部显示「当前模型：RWKV 官方 13B」；走了回落就红字标出
「XX（13B 不可用，已回落）」，不会让用户误以为在用 13B。

> 为什么必须 probe：注册表里 3 个非活动官方档案的 CF 凭据是空的，但 `isValid()`
> 只看 baseUrl 非空 → 会「看起来可用」。不探活的话请求会拿到 CF 的 HTML 登录页，
> 报错极难懂（PITFALLS §27.2）。

## 三、「最严防重复」的真机对照实验（本轮最重要的发现）

工具：`tools/rwkv_writing_bench.dart`（新增 `strict` / `strict2` / `strict3` 三个套件）。
端点：`api-7b.rwkvos.com`（真实 RWKV Cloud 7.2B），同一提示词、同一目标（≥1600 字）。

### 3.1 第一版设计（把旋钮拉满）被数据否掉

| 组合 | 字数均值 | 达标 | 退化 | ngram 最差 |
|---|---:|---:|---:|---:|
| `UNBANDED_BASE`（官方档原值） | **1732 / 1957** | 2/3 · **3/4** | 0/3 · 0/4 | 0.001 |
| `STRICT_V48`：freq .5 + dry .85 + **last_n 4096** | **481 / 644**（两轮复现） | **0/3 · 0/4** | 0/3 · 0/4 | 0.000 |

复读确实压到 0，但**字数掉 67%**，完全够不上 1600 字目标 —— 正是代码注释里
「被罚得不敢写」的形态。

### 3.2 逐个旋钮隔离（第二轮）

| 只改一处 | 字数均值 | 达标 | 退化 | ngram 最差 |
|---|---:|---:|---:|---:|
| 只抬 `alpha_frequency` 0.2→0.5 | 1168 | 1/3 | 0/3 | 0.000 |
| 只抬 `dry_multiplier` 0.8→0.85 | 427（仅 1 有效样本） | 0/3 | — | 0.005 |
| 只抬 `dry_penalty_last_n` 2048→4096 | 1684 | 1/3 | 0/3 | 0.001 |
| freq .5 + dry .85，**窗口仍 2048** | 2448 | 2/3 | 0/3 | **0.236** |

### 3.3 第三轮复测（4 次/组，确认不是抖动）

| 组合 | 字数均值 | 达标 | 退化 | ngram 最差 |
|---|---:|---:|---:|---:|
| `STRICT_V48`（含 last_n 4096） | **644** | **0/4** | 0/4 | 0.000 |
| `UNBANDED_BASE`（官方档原值） | **1957** | **3/4** | 0/4 | **0.001** |
| freq .5 + dry .85（窗口 2048） | 1358 | 1/4 | 0/4 | **0.236** |

### 3.4 两条反直觉结论

1. **「把惩罚旋钮全部拉满」≠「更防复读」**：`freq .5 + dry .85 + last_n 4096` 字数崩到
   481/644，而 `last_n 4096` 与 `freq .5` 的**组合**才是元凶（各自单独抬高时字数正常）。
2. **抬高 `frequency` 反而抬复读**：`last_n 2048` 那组 ngram 最差 **0.236**，而官方档原值
   只有 **0.001**。频率惩罚会把中文虚词（的/了/他）一起罚掉，模型被迫从更窄的分布里
   重新选词，反而更容易滑进循环。

### 3.5 最终落地的取值

```dart
const kRwkvStrictestWritingSampling = {
  'top_k': 50, 'top_p': 0.6,
  'alpha_presence': 2.0, 'alpha_frequency': 0.2, 'alpha_decay': 0.999,
  'stop_tokens': kRwkvDefaultStopTokens,
  'dry_multiplier': 0.8, 'dry_base': 1.75, 'dry_allowed_length': 2,
  'dry_penalty_last_n': 2048,   // ⚠ 固定 2048，不要拉到 4096
};
```

即：**只把唯一真正有效的旋钮（`alpha_decay`）顶到 0.999，其余保持在实测最优的官方创意档
取值**。配合**温度 1.0**（0.88 落在复读高发区）与**显式 `stop_tokens`**（事中止损）。

`alpha_decay` 是唯一例外 —— **只抬不压**：用户自己配了 0.9995 就保留，配了 0.99（官方创意
档）会被抬到 0.999。

## 四、删除所选文本

纯本地文本手术，**不调模型**：

- `deleteSelectionFrom(content, selected)`：删除选区并归一化段落间距
  （删空的段整段消失、多空行压成一个空行），选区不在正文中时抛 `StateError`；
- `ChapterAiAction.deleteSelection` 走同一套「确认对话框 → 采纳应用」通道，
  确认文案写明「不调用模型 + 无法本地撤销 + 版本号 +1」；
- 面板里它是**独立样式**（红色描边按钮，不是 tonal），因为它不是 AI 动作；
- 落库沿用 `chapter_preview_page._applyResult`（`content` / `wordCount` /
  `lastEditedAt` / `versionNumber +1`）。

离线自检 11 条（`selection_apply_selftest` E 组）：段中截断、整段删除、首/末段、
唯一段、单换行归一、空选区报错、选区过期报错、重复选区只删第一处。

## 五、AI 参考内容可手动修改

面板新增可折叠的「AI 参考内容（可手动修改）」区，三栏可编辑：
**卷大纲 / 章细纲 / 上一章结尾**，各带字数计数，改动立即对后续生成生效。

关键竞态处理：宿主页（章节预览）是**异步**装载上下文的，面板首帧拿到的是空值，
装载完成后才重发新值。若用户已手改过（`_refDirty`），异步回填必须**让位**，
否则手打的字会被冲掉 —— `didUpdateWidget` 里按「当前值 == 上次宿主值」判断，
只在用户没动过时才回填。

## 六、纲要管理（新模块）

位置：侧边栏「卷宗管理」与「章节管理」**之间**（手机端底部导航第 2 项）。

布局：左侧卷宗列表（序号 / 标题 / 章数 / 已写细纲数），右侧
「本卷大纲」编辑器 + 该卷每章的「章细纲」卡片。

### 存储位置：刻意复用既有列，不新建表

| 内容 | 存储列 |
|---|---|
| 卷大纲 | `Volumes.description` |
| 章细纲 | `Chapters.summary` |

理由：

1. AI 写作链路的上下文**早就在读这两列** ——
   `chapter_preview_page._loadAiContext` 的 `volumeOutline` 取 `vol.description`、
   `chapterOutline` 取 `row.summary`；`chapter_rewrite_service` /
   `continue_story_service` / `project_context_assembler` 读同样字段。
   在这里写，作者刚保存的细纲**立刻**成为后续所有 AI 写作的参考，零同步步骤。
2. 卷宗/章节的创建与排序仍在「卷宗管理 / 章节管理」里做，职责不重叠。
3. 避免 schema 版本升级（`schemaVersion 1 → 2` + migration），存量数据零风险。

⚠ **列宽上限 1000 字**：两列都是 `withLength(max: 1000)`，drift 在写入时会校验
（`database.g.dart` 的 `validateIntegrity` → `checkTextLength`），超出会抛
`InvalidDataException`。所以页面在保存前做字数检查并给可读错误，计数器超限变红 ——
不让异常裸奔。

## 八、遗留

- **出包未做**（本轮未要求）。改动全在源码里。
- **服务端 524 抖动**：本轮实验期间服务端频繁返回 `HTTP 524`（单次生成耗时
  20~128s），部分臂样本量不足（已在表中标注）。若要做严格 A/B，建议在服务端空闲时段跑。
- **`dry_*` 是否被服务端真正采纳**：+47 结论是「去掉 DRY 表现无差异」，本轮仍无法区分
  —— 因为最终取值就是官方 DRY 默认值，本来也不该有差异。
