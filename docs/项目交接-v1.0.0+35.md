## 新功能与接入点

1. `writing_prompt_catalog.dart`：31 个真实调用的工艺节点，保留原默认提示词的文字与动态上下文。含大纲、四种正文工艺、验收返工、润色、正文污染纠偏、审查及设定更新。
2. `writing_prompt_templates.dart`：不可变模板配置、多模板选择、变量校验、单次变量替换、JSON 存取及损坏配置提示。JSON scope/key 为 `ai_config/writing_prompt_templates`，schema version=1。
3. `writing_prompt_settings_page.dart`：节点列表、内置只读、新建副本、编辑命名、多模板选择、删除、保存及未保存退出提示。输入控制器随页面销毁释放。
4. `core/di.dart`：启动时加载模板；保存落盘成功后才发布新状态。实际存在调用方的 9 个中英文资源模板并入配置目录。未被调用的 WriterAgent/RWKV 旧资源没有伪装成可生效选项。
5. `multi_agent_book_generation_service.dart`：大纲、正文、验收、返工等改从模板渲染；DI 注入不可变配置快照，运行中的任务不更换配置。
6. `book_content_review_service.dart` 与 `module_state_service.dart`：实际请求中的角色、任务提示词均接入同一配置。
7. `PromptTemplateRegistry.withOverrides` 及 `_lazyTemplates`：双代理 / 修炼体系使用已保存资源模板，并保留旧变量语法和语言回退行为。
8. 设置页与多智能体写书向导均有配置入口。

模板按节点全局配置，不按书籍或模型分别保存。变量必须保留；JSON 输出字段的语义正确性仍依赖用户编辑和既有解析逻辑。没有增加模板联网同步或导入导出 UI。

## 构建与发布

使用 Flutter 3.38.5 / Dart 3.10.4。

Windows 在英文路径 junction 下执行 `flutter build windows --release --no-pub`，发布整个 `build/windows/x64/runner/Release` 目录。

Android 在 `S:\` 下构建，使用 `F:\30_Novelcraft_Flutter\android-build-toolchain` 的 Pub cache 与 Android SDK。上一轮构建遇到 `integration_test` 插件被注册进 release、Java 类不可见的问题。本次沿用临时移除该 dev_dependency 后构建、随后恢复依赖的流程。交付源码保留 integration_test；重新构建时若重现同类问题，应使用此已知绕行，或另行修复 Flutter 插件注册。

正式包文件名：`novelcraft_1.0.0+35_windows_release.zip`、`novelcraft_1.0.0+35_release.apk`。源代码备份含 `pubspec.lock`；不包含签名私钥、key.properties、local.properties、用户数据库、模型权重及构建缓存。复现原签名 APK 需由项目所有者另行配置现有签名材料。

最终文件大小、SHA256、签名检查和备份位置记录在工作区根目录的 `发布清单-v1.0.0+35.md`。本次没有安卓真机安装和 Windows 手工交互验收。

## 继承的未完成事项（与本次模板功能分开）

- 客座读者 UI 的开关 / 旧对象捕获、控制器生命周期及平台模型选择仍需整理；不可用的客座模型可能回退到主审查员。
- `enableSeniorReview` 尚未完整驱动运行时；13B 的复核结论尚未作为唯一的改进方案闸门。
- 旧内容审查只取末尾约 9000 字符，而自动改写对整章采用约 1400 token 预算；缺少修订备份、长度保护和并发版本校验，存在长章内容丢失风险。
- 审查后改写尚需完善项目归属校验、同步档案 / 设定及评论历史留存。
- 项目档案校准当前只处理命名和孤儿记录，不覆盖项目概览与写作档案的总字数差异。
- 通用 Agent 模块路由与所有业务模块执行器的连接仍不完整。

这些旧问题没有在本次 Prompt 配置请求中修复；旧版文档中“全自动闭环已完成”的概括不可作为验收依据。
