## 0. 这份报告回答什么问题

「要训练，先要知道模型现在什么会、什么不会。」
本报告的用途有二：

1. **决定数据集该覆盖哪些能力区间**（不能拿一个物理上不可用的区间去训练）。
2. **给后训练设验收基线**（`docs/RWKV后训练数据集格式范式-v1.0.md` §8.3 的数值目标出自这里）。

## 1. 结论速览

| 维度 | 实测结论 | 对数据集/产品的直接含义 |
|---|---|---|
| **单次正文长度** | 可用上限 ≈ **2000~2500 字**；超 2600 字 ngram 破 0.05；cap ≥ 4096 **词级复读崩壞** | 删掉「单次 3500 字以上」的样本档；整章一律**分片**构造 |
| **长文自然收束** | **6/6 失败**（全被截断或停在半句） | 「完整句收尾」必须专门练 + 质量闸兜底，不能指望自觉 |
| **结构化输出（JSON）** | **强项**：5/10/20/40 条全部 **schema 100%**、条数精确、不截断 | A1/A2 的 `count` 上限可放宽到 40；不必教「分段调用」 |
| **上下文长度** | 输入侧 **48,000 字（≈4.8 万 token）照样接受**，且**暗号复述证实 Attention 真实有效**（见 §4.5） | `tailContext` 可取到 8000 字；`acceptance` 的正文可到 30000 字 |
| **采样温度** | 在最严防重复参数下，**0.3~1.5 全都几乎零复读** | 复读主因是**惩罚参数**不是温度；教师用 0.85~1.0 即可 |
| **指令遵循** | 原始 5/8，**剥掉服务端 `>` 前缀后 7/8**；唯一真失败是「精确字数」 | 唯一短板是精确字数 → 数据集加量 |
| **分片续写（D2）** | **健康**：零回抄、跨片 ngram ≤ 0.0017 | 这是线上主路径，DPO 的 chosen 必须保持充足，别练退 |
| ⚠ **服务端 `>` 前缀** | **每条** completion 都带，与 system/stop_tokens 无关 | **已修的线上 bug**（见 §3），也是数据集的新负例 E17 |

## 2. 正文长度边界（最值得看的一条）

| max_tokens | 实得字数 | finish | 自然收束 | ngram | 收尾形态 |
|---:|---:|---|---|---:|---|
| 512 | 525 | stop | ✗ | 0.0000 | 截断（「…镇子唯一」） |
| 1024 | 1054 | stop | ✗ | 0.0000 | 截断（「…礁石产」） |
| 2048 | 2112 | stop | ✗ | 0.0000 | 截断（「…结构体」） |
| 4096 | 2633 | stop | ✗ | **0.0755** | **复读崩壞** |
| 6144 | 6356 | stop | ✗ | **0.3338** | 复读崩壞（对白循环） |
| 8192 | 3170 | stop | ✗ | **0.1438** | **复读崩壞** |

### 崩壞样本（原文摘录）

- `cap=4096` 尾部：`险峻陡峭危崖绝壁悬崖峭壁绝壁绝壁绝壁绝壁绝壁……`（同一词刷屏数十次）
- `cap=8192` 尾部：`演再次发生类似悲剧重演再次发生类似悲剧重演再次发生……`
- `cap=6144` 尾部：`“那么请问有什么需要我配合调查工作方面事项吗？”\n电话那头传来回答声音：“暂时还没有具体安排……”`（对白结构循环）

### 三条结论

1. **单次可用上限 ≈ 2000~2500 字。** 这正好落在 `LayeredBookConfig.sliceChars = 1400` / `maxSlicesPerChapter = 4` 的设计上 —— **分片不是权宜，是必需**。
2. **不能依赖自然收束。** 6/6 全失败：要么被 `max_tokens` 砍断，要么模型自己停在半句。⇒ 「末字符必须是句末标点」这条闸（E9）必须有，而且必须配整章重试。
3. **首行普遍带 Markdown 标题**（`# 第一章：退潮时分` / `## 一、钟声与脚步声`）。⇒ 第 2 类污染（围栏/标题）在正文链路的清洗必须保留。

## 3. ⚠ 重大发现：服务端给每条 completion 加 `>` 前缀

### 对照实验（3 次）

| 请求 | 原始 content |
|---|---|
| `只回复一个字：好`（无 system） | `>好` |
| 同上 + `system` | `>好` |
| 同上，不带 `stop_tokens` | `>好` |

字节固定 `[62, …]`（0x3E = `>`）。**与 system、stop_tokens、提示词内容全都无关** ⇒ 这是**服务端 chat 模板行为**，不是模型能力。

### 它造成了什么

分层管线的结构化调用走 `LayeredBookGenerationService.cleanStructured`，而它**原先不剥 `>`**。于是：

```
模型原文:  >标题：《潮声与灯塔》
BriefPatch._fieldLine 的 ^\s*标题 匹配失败
        ⇒ parseFields 丢掉「标题」字段
        ⇒ 章名退化成「第 N 章」
```

（正文链路不受影响，因为它走 `AIOutputSanitizer.extractCleanOutput`，里面的 `_stripLeadingQuoteBlock` 早就会剥 —— 注释里记载这是 2026-09-17 在 g1j 上就观测到的同类现象。）

### 已修（+52）

`cleanStructured` 开头新增 `_stripLeadingQuotePrefix()`：

- 只剥**开头连续**的 `>`（跳过开头空行后再判断），**不碰正文里合法的引用**。
- 新增 **9 条回归自检**（`layered_pipeline_selftest` M 组）：开头剥离 / JSON 前剥离 / 非开头保留 / 空行后剥离 / 幂等不变。

### 为什么这件事对数据集同样关键

| 问题 | 答案 |
|---|---|
| 要不要让教师产出的样本带 `>`？ | **不要。** 那是这台服务端的模板行为，换服务端就没有了；学进去只会制造脆弱性。 |
| 要不要把它当负例？ | **要。** 新增错误码 **E17**：`rejected` = 带 `>` 前缀，`chosen` = 不带。 |
| 生成流水线要在哪一步剥？ | **阶段 2（确定性清洗）的第一步**，在任何契约校验之前 —— 否则 `>标题：…` 会被字段解析判成「缺字段」。 |

## 4.5 上下文 Attention 边界（暗号复述）

> 补 `context` 套件的缺口：那个套件只验证「服务端不报错」，不验证模型**真的读到**。

做法：在前文第 N 字处埋一句「守塔人老岑压低声音念了四个字：『青柏归舟』」，然后要求原样复述。

| 前文总长 | 暗号位置 | 命中 | 模型输出 |
|---:|---:|---|---|
| 20,000 字 | 第 500 字 | **✓** | `青柏归舟` |
| 20,000 字 | 第 10,000 字 | **✓** | `青柏归舟` |
| 30,000 字 | 第 25,000 字 | **✓** | `青柏归舟` |
| 40,000 字 | 第 20,000 字 | **✓** | `青柏归舟` |
| 40,000 字 | （对照）问一个前文没提的问题 | — | **`未提及。`** |

**结论：Attention 是真实的，不是「接收但不读」。**
- 4.8 万 token 的输入，暗号放在**前段 / 中段 / 后段**都能准确复述。
- **对照组更重要**：问一个前文里没有的事实时，模型老实回答「未提及」而不是编造 ——
  说明上面的「命中」是真检索，不是猜的。

⇒ 数据集可以放心使用长前文；第 5 节原来那句「未验证 Attention」的保留意见**已解除**。
