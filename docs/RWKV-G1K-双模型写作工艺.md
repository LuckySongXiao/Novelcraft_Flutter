# RWKV G1K 2.9B + 7.2B 双模型写作工艺

适用入口：多智能体写书，默认「续写优选（beam）」工艺。依据根目录《四尺寸手册v1.md》及《新一代模型T10修订补丁_20261004.zip（报告v1.1+T≤1/新一代模型四维甜点配置报告.md》（2026-10-04 晨间修订）；吞吐、稳定性数据仅来自报告中的有限样本，不保证不同时段可复现。

## 配置

1. AI 配置的 RWKV Cloud 已内置官方 1.5B、3B、7B、13B 端点，可从端点列表切换，也可添加自定义名称和 API 地址。官方模板不预填 API Key、模型名或 Cloudflare Access 凭据；API Key 可选，官方服务所需的 CF 凭据由用户在配置页填写，勿写入仓库。
2. 选择端点或切换到 RWKV Cloud 时，应用会从当前 API 地址请求 `/models`。模型列表来自服务端，不会在鉴权/网络失败时显示伪造的默认模型；有多个模型时需在下拉框选择，已选模型和凭据按端点分别保存。添加自定义端点后，可在该端点单独填写 API Key、CF 凭据并选择模型。
3. 为 G1K 工艺选择 7B 端点，填写 Cloudflare Access 凭据后「保存并注册」并测试连接，再在 MainAgent / SubAgent 卡片点击「预置 G1K 7.2B 主编 + 2.9B 写手」。预设从 7B/3B 的 `/v1/models` 匹配并保存**完整**模型 ID 到独立写书配置 `ai_config/book.g1k_preset`，不覆盖云端凭据和普通双代理设置；端点不可达、无匹配或多个版本时保留原选择。卡片可单独「停用写书预设」。
4. 应用内预置 `rwkv7-g1k-7.2b` / `rwkv7-g1k-2.9b` 家族匹配规则，**不是**猜测的完整 ID。用户也可手动填写端点返回的完整 ID；启动写作前再次校验。
5. 多智能体写书会临时建立独立的 `https://api-3b.rwkvos.com/v1` 通道，沿用已配置的 CF 鉴权，结束后释放。默认 `beam` 工艺下，MainAgent 负责主线、分卷、章节大纲与逐段润色；SubAgent 负责正文续写。

## 参数与验收

- G1K 云端写作：`temperature` 钳到 **0.88-1.0**（默认请求低于 0.88 则取 0.88，短稿重试 1.0）、`top_p=0.7`、`presence_penalty=2`；不叠加原 G1J 的 DRY/alpha 双重惩罚。旧版 `T=1.2` 结论已被晨间复测降级；7B 规划最多 1500 tokens、短段润色请求 1200 tokens，2.9B 正文每发最多 **1200 tokens**，仍受上下文和用户输出预算约束。
- 2.9B 单段目标约 1100 字，上限 1200 字，正文提示明确「至少写满 N 字」并禁止字数自报；少于 800 字（最后一段按剩余字数比例）时以 `T=1.0` 重采样一次。注意 **1200 tokens 不等于保证得到 1200 字**，2.9B 的早停仍须靠长度闸拦截。识别同一句出现三次时截断到第二次出现之前，弃掉复读尾部并阻止污染下一段锚点；每段继续经过段落复读、大纲污染和前文重合评分。
- 7B 润色按不超过 850 字的片段进行；缩水超过 10% 或评分下降过大时保留 2.9B 原稿，润色结果也过句子循环闸。源报告 7B 3500-token 单发 6/6 出现后半段复读环，因此不能将其当作单发整章方案。
- 最终章继续经过既有字数与重复率质量闸；未达标保存为草稿，不标记已完成。报告中的“至少 2/4 候选满额”“摘要合格率 95%”不是当前功能的已验证承诺。

## 边界

新报告推荐 **7B 做分段正文主力、2.9B 做幕卡深化/过渡段**，与用户既定的「7B MainAgent 规划润色、2.9B SubAgent 正文」分工不一致。本次**不擅自交换角色**，以 2.9B 短段、短稿重试和复读闸降低风险；正文最终质量仍须真实云端试产验证。报告中的凌晨 N=8 和白天拥堵结论具有时段性，本次不将 N=8 硬编码为固定并发，也不对所有用户强制夜间写作。

独立的一键成书、普通双代理写作与 `solo`/`duo`/`team` 章节工艺未切换到本混合润色链；预设只用于多智能体写书服务，不影响其他入口及用户已有模型设置。当前只有一个在配置页持久化的 RWKV Cloud provider；3B 通道仅在多智能体写书运行时创建，不会更改全局默认云端端点，也不支持其他 API 调用共用此通道。未点击预设或未配置 G1K 模型时维持原有行为。打包不包含任何 CF 密钥，发布后的用户仍须自行设置凭据。
