# RWKV 后训练数据集 · 内容格式范式 v1.0

> 适用范围：NovelCraft 项目专用 RWKV 模型的后训练（SFT 为主、DPO 为辅）数据集。
>
> **Part II（State Tuning 专项）见 `docs/后训练数据集格式范式-StateTuning追加-v1.0.md`。**
> State Tuning 是 RWKV-PEFT 官方支持的独立微调路径（`--train_type state`），
> 产物是可单独挂载的 `.pth` state 文件，与 LoRA 并列但**数据要求完全不同**：
> Part I 允许异构数据混一份，Part II 要求**一个 state 只许一种输出形状/人格**。
> 本文件定义的任务族、负例谱系、G1~G8 闸位在 Part II **全部继续适用**。  
> 生成方：**QWEN3.8-27B**（教师模型）。消费方：RWKV 7B（本项目线上部署的 `rwkv7-g1k-7.2b-20260930-ctx25600` 及其后续微调版本）。  
> 范式版本：`v1.0`，对应代码版本 `1.0.0+51`。

## 0. 为什么需要这份范式

### 0.1 三个前提

1. **RWKV 的能力短板是「工艺性」的，不是「知识性」的。** 它不缺中文语料，缺的是**在这套四级管线里按契约干活**：输出恰好 8 个字段的细纲、恰好是 JSON 对象数组、绝不回抄前文、绝不复读同一节拍、绝不在章末写「（全文完）」。
2. **线上运行时是「提示词 + 解析器 + 质量闸」的刚性组合。** 模型输出只要偏离契约一个字，解析器就降级、质量闸就拦、整章就得重试。所以后训练的目标不是「写得更好看」，而是**把契约内化成默认行为**。
3. **教师模型生成的样本必须与运行时逐字对齐。** 如果数据集里的 prompt 和线上实际下发的 prompt 不一致，模型学到的是「另一个任务」。因此本范式的第一条铁律是：

> **铁律 1：数据集里的 `prompt` 必须与运行时构造的字符串逐字一致（含换行、全角标点、⚠ 符号）。**

### 0.2 与「通用写作数据集」的区别

| 维度    | 通用写作数据集 | 本范式                         |
| ----- | ------- | --------------------------- |
| 任务定义  | 「写一段小说」 | 25 个**契约化**子任务（见 §2）        |
| 输出校验  | 人工/模型打分 | **确定性解析器**（可执行断言）           |
| 负例来源  | 随机扰动    | **实测真实故障谱系**（§4，16 类）       |
| 长度要求  | 不定      | 每族有硬区间（§5）                  |
| 一致性要求 | 无       | 伏笔章号必须落在本书范围内、跨度 ≥2、字段不得互相同 |

| 字段                    | 类型          | 必填 | 说明                                              |
| --------------------- | ----------- | -- | ----------------------------------------------- |

| `source.*`            | —           | ✔  | 用于**按书切分**，防泄漏                                  |
| `meta.difficulty`     | enum        | ✔  | `easy`｜`medium`｜`hard`（§5.3 定义）                 |
| `quality.gates`       | string[]    | ✔  | 通过的闸；未全过者**不得**进 `train`                        |

### 1.3 DPO 样本外壳（`dpo/*.jsonl`）

```json
{
  "id": "DPO-F1-000042",
  "task": "T06_prose_slice",
  "prompt": { "system": "…", "user": "…" },
  "chosen": "（合格 completion）",
  "rejected": "（同一 prompt 下的真实故障 completion）",
  "error_kind": "E8_repetition_degeneration",
  "error_evidence": {

  },

> **要求**：`chosen` 与 `rejected` 必须是**同一个 prompt** 下的两个真实输出（教师版 vs 小模型版），不要用「人工改写」冒充。`same_prompt` 是唯一允许的配对方式；禁止 `cross_prompt` 配对（会教出与内容无关的偏好）。

## 3. 逐任务规范

> 说明：`§3.x.2` 的 prompt 模板**逐字取自代码**，变量用 `{{var}}` 标出。生成数据时必须把变量替换为真实值，替换后**不得**增删任何字符（含空格与换行）。

### 3.1 A1 / A2 · 里程碑（JSON 对象数组）

**3.1.1 用途**  
把「起点锚 → 终点锚」这条剧情弧线**均分成 N 段**，给出每段结束时必须到达的状态。A1 用于卷（N = 卷数），A2 用于章（N = 每卷章数）。这是「线性补齐」的唯一载体。

**3.1.2 prompt 模板**

`system`：

```
你是长篇小说总编剧。只输出要求的 JSON 数组，不要解释、不要 Markdown 围栏。
```

（A2 时同文，仅 `unitZh` 由「卷」改为「章」。）

`user`：`LayeredPrompts.milestonePlan` 的完整输出，结构为：

```
任务：把一条剧情弧线**均分成 {{count}} 段**，给出每一段结束时必须到达的状态。

【作品设定】
{{worldContext}}

{{anchor.render()}}

【线性推进要求（重要）】
- 整条弧线从「{{startLabel}}」走到「{{endLabel}}」，请把它**均匀切成 {{count}} 段**；
- 第 i 段结束时，剧情应推进到整条弧线的约 i/{{count}} 分位：第 1 段只完成 {{pct1}}%，第 {{count}} 段必须**恰好**到达「{{endLabel}}」；
- **不要**在第 1 段就把终点事件写完，也**不要**到最后一段还停在起点状态；
- 每段的状态描述要写「人物处境 + 已解决什么 + 新暴露什么」，40~80 字，具体到可判定，不要写「继续推进」这类空话。
{{extra 行，若有}}

【字段含义（务必按此填，别填反）】
- `label`：{{labelHint}}
- `endState`：{{stateHint}}

只输出 JSON **数组**（数组元素必须是**对象**，不是字符串），不要解释、不要 Markdown 围栏：
{{jsonExample 或默认示例}}

⚠ 硬性格式要求：回复的**第一个字符必须是 `[`**，最后一个字符必须是 `]`；禁止在 JSON 前后写任何说明文字、标题、分隔线或 Markdown 代码围栏。
```

其中 `anchor.render()` 的形态为：

```
【剧情弧线】
起点：{{start}}
终点：{{end}}
```

**3.1.3 completion 契约**

- `format.kind = json_array`；元素必须是 **object**（**不是**字符串）。
- 每元素字段：`index`（int，1 起、连续、与数组下标一致）、`label`（8~~14 字文学化名称）、`endState`（40~~80 字）。
- 元素个数**恰好** `count`。
- 首字符 `[`，末字符 `]`；**零**前后缀文字、**零** Markdown 围栏。

**3.1.4 正例（A1，count=3）**

```json
[{"index":1,"label":"退潮四十分钟","endState":"沈砚在第一次夜班中撞见退潮异象，独自走进低潮图书馆，借走写着自己名字的第一本书，但对代价一无所知。"},{"index":2,"label":"借阅卡的背面","endState":"沈砚改写了一次小事故并尝到甜头，随即发现每次改写都会让一个熟人从他的记忆里淡去，他开始怀疑编目员的身份。"},{"index":3,"label":"永久淹没","endState":"百年大潮到来，沈砚查明编目员就是上一个借阅者，选择放弃最后一次改写机会，让图书馆与自己的记忆一同沉入海底。"}]
```

**3.1.5 负例**

| #  | 错误形态                              | 违反                    | 修正                              |
| -- | --------------------------------- | --------------------- | ------------------------------- |
| N1 | `["沈砚走进图书馆","沈砚发现真相","沈砚做出选择"]`   | 元素是字符串而非对象（**实测最常见**） | 补全为 `{index,label,endState}` 对象 |
| N2 | 前面带开场白：`好的，这是三卷里程碑：\n[...]`       | 污染                    | 删掉首个 `[` 之前的一切                  |
| N3 | 用 ` ```json ` 围栏包裹                | 污染                    | 剥离围栏                            |
| N4 | `endState` 全写「继续推进剧情」             | 空话，无法判定               | 改为「人物处境 + 已解决 + 新暴露」            |
| N5 | 5 个对象但 `count=3`                  | 数量不符                  | 截断/重生成到恰好 `count`               |
| N6 | `{"index":1,"label":"…"}`（单对象非数组） | 结构错误                  | 包成数组                            |

**3.1.6 自动校验器（可执行）**

````
V-A1-1  trim 后首字符 == '[' 且末字符 == ']'
V-A1-2  jsonDecode 成功且为 List
V-A1-3  every(item is Map)
V-A1-4  length == count
V-A1-5  index 序列 == [1..count]
V-A1-6  every(label.trim().isNotEmpty && label.length 在 6..20)
V-A1-7  every(endState.length 在 30..100)
V-A1-8  !RegExp(r'```|好的|以下是|这是').hasMatch(原文)  # 无污染
V-A1-9  endState 互不重复（相似度 < 0.9）
````

**3.1.7 配比**：A1 : A2 = 1 : 6（A2 调用次数是 A1 的 `卷数` 倍）。难度分层见 §5.3。

### 3.2 C1 · 章节细纲（8 字段 + 可选伏笔小节）★ 最高优先级

**3.2.1 用途**  
把「本章起点 → 本章终点」这一章的弧线，落成 **8 行结构化细纲**；若本章埋了线，追加 `## 伏笔提示` 小节。这是全链路最关键的一环：**细纲质量直接决定正文复读率**（实测：细纲字段复制 → 正文反复写同一节拍，ngram 0.154；字段互不重复 → ngram 0.032）。

**3.2.2 prompt 模板**

`system`：`你是长篇小说分卷编剧。只输出要求的 JSON 数组…`（**注意**：C1 复用该 system 字符串以保持与运行时一致）

`user`：`LayeredPrompts.chapterBrief` 的完整输出：

```
任务：为《{{chapterLabel}}》（全书第 {{globalOrder}}/{{totalChapters}} 章，所属《{{volumeLabel}}》）撰写章节细纲。

【作品设定】
{{worldContext}}

【本卷大纲】
{{volumeOutline}}

【本章起点 → 本章终点】
起点（上一章结束时的状态）：{{previousChapterState 或 '本卷开篇'}}
终点（本章结束时必须到达）：{{chapterMilestone.endState}}

{{foreshadowObligations 块，若有}}

请严格按以下 8 行输出（不要 Markdown 标记、不要解释）：
⚠ 8 行必须**各写各的、内容互不重复**（尤其「本章目标 / 核心冲突 / 关键转折」三者绝不能是同一句话——实测这种字段复制会让正文反复写同一个节拍、直接推高复读率）。
标题：《本章正式章名》
本章目标：…
承接上文：…
核心冲突：…
关键转折：…
章末钩子：…
出场人物：…
故事时间节点：…

⚠ **伏笔登记规则**：只要本章出现了「留下未解疑问 / 提前暗示 / 只说了一半」的写法，就**必须**在 8 行之后登记一条（不要只把它写在正文里却不在细纲登记）；确实一条都没有，才整节省略。格式：
## 伏笔提示
- T{{pad3(globalOrder)}}（第{{globalOrder}}章 → 第{{payoffExample}}章）：<一句话方向，≤50 字>
（编号用真实数字；回收章必须晚于埋线章至少 2 章、且**不超过全书 {{totalChapters}} 章** —— 上面这行只是格式示例，若本章没有伏笔就整节省略，**不要照抄示例的章号**。）

⚠ 禁止输出上面这些示例行本身（不要写 `Txxx`、`第A章`、`…` 占位符）；第一个字符必须是 `标`（即直接以「标题：」开头），不要写任何开场白或收尾语。
```

> **末章特例**：当 `globalOrder + 2 > totalChapters` 时，模板最后一段替换为：
>
> ```
> ⚠ 本章距全书结尾已不足 2 章，**不要再埋新的伏笔**（埋了也收不回来）—— 不要输出伏笔小节。
> ```
>
> 数据集必须**同时**覆盖「可埋线」与「禁埋线」两种形态。

**3.2.3 completion 契约**

- `format.kind = text_lines`，`contract_ref = kChapterBriefFields`。
- **恰好 8 行**，顺序固定：  
  `标题：` `本章目标：` `承接上文：` `核心冲突：` `关键转折：` `章末钩子：` `出场人物：` `故事时间节点：`
- 第 1 行格式：`标题：《章名》`（章名 8~14 字，不含卷号/章号/书名/标点/大纲字段词）。
- **8 个字段值两两互不重复**（尤其目标/冲突/转折）。
- 可选第 9 段：`## 伏笔提示` + 若干 `- Txxx（第A章 → 第B章；提醒第C章）：方向` 行。
  - `A < B`，`B - A >= 2`，`1 <= A,B,C <= totalChapters`。
  - 方向 ≤50 字，**越模糊越好**（不得写具体剧情内容）。
- 首字符必须是 `标`（无开场白）；无收尾语。

**3.2.4 正例**

```
标题：《潮声与灯塔》
本章目标：沈砚在第一次夜班中撞见退潮异象，决定独自去东岬看一眼。
承接上文：他刚接手夜班，与周晓棠只是在派出所门口点过一次头。
核心冲突：镇上的老规矩与他的好奇心跳在了一起——去，就违背了老岑的告诫。
关键转折：他在礁石旁捡到一枚刻着自己名字的旧借阅卡。
章末钩子：海水开始回涨，而图书馆的门还没开。
出场人物：沈砚、老岑
故事时间节点：入秋第三日，夜班第一晚

## 伏笔提示
- T003（第3章 → 第18章；提醒第11章）：一件旧物上的名字被反复提及，来历未明。
```

**3.2.5 负例（★ 本任务族是负例最密集的地方）**

| #  | 错误形态                             | 违反              | 修正            |
| -- | -------------------------------- | --------------- | ------------- |
| N1 | `本章目标 == 核心冲突 == 关键转折`（逐字相同）     | **字段复制（实测最高频）** | 三行各自写成不同事件    |
| N2 | 输出 9 行（多了「本章要点：」）                | 行数与字段不符         | 删多余行          |
| N3 | 回抄示例：`- Txxx（第A章 → 第B章）：<一句话方向>` | 模板占位回抄          | 换成真实编号与章号     |
| N4 | 示例章号泄漏：5 章的书里出现 `第28章`           | 越界伏笔            | 回收章必须 ≤ 本书总章数 |
| N5 | 以 `好的，这是本章细纲：` 开头                | 开场白             | 直接从 `标题：` 起   |
| N6 | 末尾附「请自查 ① ② 有问题就修正」              | **指令回显**        | 截断            |
| N7 | 用 Markdown 加粗 `**本章目标**：…`       | 标记污染            | 去 `**`        |
| N8 | 伏笔跨度 1 章（`第5章 → 第6章`）            | 跨度纪律            | `B - A >= 2`  |
| N9 | 末章仍输出伏笔小节                        | 末章禁埋            | 整节省略          |


**3.2.6 自动校验器**

````
V-C1-1  BriefPatch.parseFields(completion).length == 8
V-C1-2  8 个键名与 kChapterBriefFields 完全一致（顺序可比对）
V-C1-3  BriefPatch.duplicatedFields(completion).isEmpty     # 关键
V-C1-4  BriefPatch.looksLikeBrief(completion) == true
V-C1-5  !completion.trimLeft().startsWith(RegExp(r'好的|以下是|这是|请'))
V-C1-6  !RegExp(r'\*\*|^#(?!\s*伏笔提示)|```').hasMatch(...)   # 无 Markdown
V-C1-7  伏笔小节若存在：每条 ForeshadowLedger 解析成功
V-C1-8  伏笔章号 ∈ [1, totalChapters] 且 span >= 2
V-C1-9  末章（globalOrder + 2 > total）不得含伏笔小节
V-C1-10 章名不含 大纲字段词（ChapterTitleParser._metaLabels）
````

**3.2.7 配比**：C1 应占全数据集**总样本数的 18%~22%**，是最大单族。其中含伏笔小节的 ≥ 35%，末章禁埋形态 ≥ 5%。

### 3.3 C2 · 细纲差异补丁 ★

**3.3.1 用途**  
对 C1 的产物做**独立核验 + 修正**。关键设计：**只回需要修改的字段行**，而不是重发整份细纲。

> 实测依据：要求「重发整份细纲」时，模型把核验清单本身抄进输出 → 4/5 次被契约校验判废；改成「只回补丁」后，平均 ngram 0.169 → **0.032**。

**3.3.2 prompt 模板**

`system`：`你是长篇小说细纲审校。只输出需要修改的字段行，不要解释。`

`user`：`BriefPatch.selfCheckPrompt`：

```
【待核验的章节细纲】
{{brief}}

请核验以下 4 点：
① 本章终点「{{milestoneEndState}}」是否已在细纲里落实（本章目标/关键转折/章末钩子要有对应）；
② 承接上文是否与上一章状态一致；
③ 伏笔提示格式是否为 `- Txxx（第A章 → 第B章）：方向`，章号在 1~{{totalChapters}} 之间；
④ 八个字段的内容**必须互不重复**（目标/冲突/转折不能是同一句话）。
{{若检出重复：   ⚠ 已检出重复：{{dup.join('、')}} —— 这几项必须改写。}}

【输出格式（务必遵守）】
**只输出需要修改的字段行**，每行 `字段名：新内容`；不需要修改的字段**不要输出**；
如果全部合格，只回复两个字：`无需修改`。
⚠ 不要复述上面的核验清单（不要写「请核验」「①」「如果全部合格」这类字），不要写任何解释、开场白或收尾语。
示例（只示意格式，内容按你的判断写）：
关键转折：<改写后的转折>
章末钩子：<改写后的钩子>
```

**3.3.3 completion 契约**

两种合法形态，**互斥**：

- **形态甲（有需改项）**：仅包含 `字段名：新内容` 行，字段名必须 ∈ `kChapterBriefFields`。**不得**包含未修改字段、不得包含核验清单文字、不得包含解释。
- **形态乙（无需修改）**：仅 `无需修改`（等价写法白名单：`无` `合格` `全部合格` `无需改动` `没有需要修改的字段`；空串亦等价）。

**3.3.4 正例**

形态甲：

```
核心冲突：沈砚必须在「救下周晓棠」与「保住自己的记忆」之间二选一。
关键转折：他发现借阅卡背面的名字是自己父亲，而父亲二十年前也进过那座图书馆。
```

形态乙：

```
无需修改
```

**3.3.5 负例**

| #  | 错误形态                     | 违反                |
| -- | ------------------------ | ----------------- |
| N1 | 重发整份 8 行细纲               | 形态不符（这是最初设计的失败模式） |
| N2 | `请核验以下 4 点：\n① …\n② …`   | 指令回显              |
| N3 | `关键转折：…\n\n以上就是需要修改的内容。` | 收尾语               |
| N4 | `标题：` 也一并输出（其实没改）        | 输出未修改字段           |
| N5 | `本章目标改为：…`               | 格式不符（缺 `字段名：` 前缀） |
| N6 | `字段名：新内容` 里字段名不在契约内      | 非法字段              |

**3.3.6 自动校验器**

```
V-C2-1  若 isNoChange(completion)：必须命中白名单（或空串）
V-C2-2  否则：BriefPatch.parseFields(completion).keys ⊆ kChapterBriefFields
V-C2-3  否则：keys.isNotEmpty
V-C2-4  !RegExp(r'请核验|①|②|③|④|如果全部合格|以下是|以上').hasMatch(completion)
V-C2-5  BriefPatch.apply(brief, completion) 后 duplicatedFields 必须为空   # 端到端
V-C2-6  apply 后 looksLikeBrief == true
```

**3.3.7 配比**：C2 与 C1 数量比 ≈ 1 : 1（每次 C1 都跟一次 C2）。其中「无需修改」: 「有需改项」= 4 : 6（实测模型更常需要改）。

### 3.4 D1 / D2 · 正文（散文）★

**3.4.1 用途**  
正文是最终产物。D1 一次写完整章；D2 分片串行续写（片内串行、章间并行）。**核心训练目标：不复读、不回抄、不停在半句、不写收尾语。**

**3.4.2 prompt 模板（D2 · proseSlice）**

`system`：`你是一位中文小说作家。只输出正文，不要解释、标题、字数统计。`

`user`：

```
任务：写《{{bookTitle}}》《{{chapterLabel}}》的正文{{isFirstSlice ? '（从本章第一句开始）' : '（第 {{sliceIndex}} 片，紧接上文续写）'}}。
背景：{{worldContext}}
本章细纲：
{{chapterBrief}}

{{foreshadowBlock}}

【前文末尾（仅供衔接上下文，**不要输出这一段**）】
{{tailContext}}

请紧接上文写下去。只输出**新增**的正文，第一句不得与前文末尾重复。
篇幅：本片不少于 {{askChars}} 字的成稿正文。这是硬要求。
```

（D1 · `Book/soloChapter` 的纪律条款另见代码：3 条纪律 + `{{styleRules}}`。）

**3.4.3 completion 契约**

- `format.kind = prose`。
- 长度：D2 单片 `>= askChars`（`askChars ∈ [600, 2400]`）；D1 整章 `>= targetChars`（默认 1600，上限按 §11 实测边界）。
- **零**标题行、**零**大纲条目复述、**零**解释、**零** Markdown。
- **零**收尾语（`（全文完）` `（完）` `全文完` `THE END`）。
- **末尾必须是完整句**（以 `。！？”）…` 之一结尾），**不得**停在 `，、：“（`。
- 跨片复读：新片与已写全文的 ngram 重叠率 ≤ 阈值（§6 G3）。
- 不得回抄 `tailContext`（开头 12 字不得与 tail 末 12 字相同）。

**3.4.4 正例（节选）**

```
油灯的火苗在供桌上一缩，沈砚听见了自己的心跳。
他本来只是想确认那扇门是不是真的存在——老岑说退潮的四十分钟里，东岬会浮出一截台阶，台阶通向一座不该有的房子。他当时没信。现在他站在防波堤的尽头，看见那截台阶从水里一节一节地长出来，像谁在水底慢慢伸直了手指。
海水退去的声响很奇怪，不是哗啦，是一种更旧的、纸张翻动的声音。
```

**3.4.5 负例**

| #  | 错误形态                      | 违反       | 检测                            |
| -- | ------------------------- | -------- | ----------------------------- |
| N1 | 同一句对白连写三遍                 | **复读退化** | `isDegenerate` / ngram > 0.18 |
| N2 | 开头回抄前文末尾 30 字             | 回抄       | 前缀比对                          |
| N3 | 结尾停在 `……他抬起`              | 中途断句     | 末字符 ∈ `，、：“（`                 |
| N4 | 结尾写 `（全文完）`               | 收尾语      | 正则                            |
| N5 | 首行 `第3章 潮声与灯塔`            | 标题污染     | 正则                            |
| N6 | `本章目标：…` 复述大纲             | 大纲回抄     | 与 brief 字段比对                  |
| N7 | 输出 `好的，我来写这一章。`           | 开场白      | 正则                            |
| N8 | 全篇 200 字（远低于 askChars）    | 长度不足     | 字数闸                           |
| N9 | 出现 `User:` / `Assistant:` | 角色标记泄漏   | 正则                            |

**3.4.6 自动校验器**

```
V-D1  length >= askChars * 0.9
V-D2  RepetitionGuard.isDegenerate(completion) == false
V-D3  charNgramRepeatRatio(completion) <= 0.05
V-D4  末字符 ∈ {'。','！','？','”','）','…'}
V-D5  !RegExp(r'（全文完）|（完）|全文完|THE END|好的|以下是').hasMatch(...)
V-D6  !completion.startsWith(tail 末 12 字)
V-D7  不含 brief 的字段标签行
V-D8  不含 'User:' / 'Assistant:' / 'System:'
V-D9  cjk_ratio >= 0.85
V-D10 段落重复率 <= 0.05
```

**3.4.7 配比**：D 组合计占 30%~~35%。D2 是 D1 的 2~~3 倍（分片是线上主路径）。长度必须**铺满** §11 测出的可用区间。

### 3.5 E 组 · 选节编辑（局部手术）

**3.5.1 prompt 模板（`SelectionEditService.buildPrompt`）**

`system`：`你是一位中文小说作家。只输出本次处理的片段，不要解释。`

`user`：

```
任务：{{operation}}
作者要求（优先于默认操作）：{{instruction}}
卷大纲：{{volumeOutline}}
章大纲：{{chapterOutline}}
上一章结尾：{{prevChapterTail}}
{{foreshadowBlock}}
<before>{{before}}</before>
<selection>{{selected}}</selection>
<after>{{after}}</after>
只输出本次处理的片段，不输出 before/after、标题、标签、解释或原文对照。
{{lengthRule}}
```

其中 `operation` 按动作取值（**逐字**）：

- `rewrite` → `按作者要求改写选区`
- `dedupePolish` → `删除重复和无效表述，再润色选区，不为凑字数扩写。`
- `expand` → `依据大纲扩写选区的动作和细节，不改变既定事实。`
- `continueWrite` → `仅输出紧接选区的新增正文，不重复选区，不复述后文。`

`lengthRule`：

- `continueWrite`：`\n篇幅要求：本次续写目标约 {{target}} 字（下限 {{target/2}} 字），要写出一个完整的场面，不要一两句话就收。`
- 其它：`\n篇幅要求：本次扩写目标约 {{target}} 字。`

**3.5.2 completion 契约**

- 只输出**处理后的片段**本身。
- **零** `<before>` / `<selection>` / `<after>` 标签、**零** 标题、**零** 解释、**零** 原文对照。
- `rewrite` / `dedupePolish`：长度与原选区同量级（0.6×~1.6×）。
- `expand`：长度 ≥ 1.3× 原选区。
- `continueWrite`：**不得**以原选区结尾 12 字开头；长度 ≥ target/2。

**3.5.3 负例**

| #  | 错误形态                             | 违反         |
| -- | -------------------------------- | ---------- |
| N1 | 输出 `<selection>…</selection>` 包裹 | 标签泄漏       |
| N2 | 先写「原文：…」再写「修改后：…」                | 原文对照       |
| N3 | `continueWrite` 从选区末句重复起笔        | 重复选区       |
| N4 | `expand` 只扩了 5 个字                | 扩写不足       |
| N5 | `rewrite` 把事实改了（人物死而复生）          | 事实漂移（需人抽检） |
| N6 | 附加「希望您满意」                        | 收尾语        |

### 3.6 A3 · 章名批量命名

**completion 契约**：`{"names":[{"i":1,"name":"章名"},{"i":2,"name":"章名"}]}` —— 严格 JSON 对象，`names` 数组长度 == 输入条数，`i` 连续。  
**禁止**：章名含卷号/章号/书名/书名号/引号/标点；含大纲字段词（`目标` `本章` `伏笔` `钩子` …）；相邻章名重复。  
**校验**：`ChapterTitleParser.reliable == true`；每名 8~14 字；`_metaLabels` 零命中。

### 3.7 A5 · 验收与设定抽取

**completion 契约**：严格 JSON 对象，三键 `paragraphs` / `report` / `updates`（结构见 `Book/acceptance` 模板）。`accepted=false` 必须带具体 `problems`。`updates` 无变更时给 `[]`（**不得**省略键）。  
**校验**：JSON 可解析；三键齐备；`updates[].target ∈ {character,world,faction,plot,timeline}`；`action ∈ {update,create}`；`field` ∈ 合法枚举。

### 3.8 B1~B3 · 大纲（结构化散文）

**B1 主线大纲**：1000~~1800 字，条目化，必须含「核心冲突 / 主角成长线 / 主要人物名单 / 世界观要点 / 分卷推进脉络 / 结局方向」六项。  
**B2 分卷大纲**：600~~1200 字，条目化，必须显式给出「本卷开局状态」与「卷末状态（下一卷起点）」。  
**B3 章节大纲**：**第一行必须是 `标题：《本章正式章节名》`**，随后 200~400 字含「本章目标 / 出场人物 / 场景与时间线 / 关键冲突与转折 / 章末钩子」。  
**共同负例**：首行缺失、章名含 `第N章`、把大纲写成散文、把 `{{styleRules}}` 当内容输出。

| **E13** | 空产出            | 只有思考无正文                  | `stripThink` 后为空                     | 重生成         | D（`/state` 特有） | 触发思考预算耗尽                                                            |               |         |          |
| **E14** | 元信息污染章名        | `《第4章：地下交易标题：血色契约【本章目标》` | `ChapterTitleParser.reliable==false` | 提取纯章名       | A3/B3          | 让教师吐单行大杂烩                                                           |               |         |          |
| **E15** | 角色标记泄漏         | 出现 `User:` `Assistant:`  | 正则                                   | 删除          | D              | 追加角色标记                                                              |               |         |          |
| **E16** | 长度塌陷           | 远低于 askChars             | 字数闸                                  | 补足到下限       | D              | 提高 frequency 惩罚诱导                                                   |               |         |          |
| **E17** | **服务端 `>` 前缀** | `>标题：…` / `>[…]` / `>正文` | `^\s*>`                              | 剥掉开头连续的 `>` | A/B/C/D        | +51 实测：本部署**每条** completion 都带前缀 `>`，与 system/stop_tokens 无关（§11.7） |               |         |          |

**负例构造铁律**：**只做「已知故障」的确定性变换**，不要用「随机删改」——随机扰动会引入与真实分布无关的噪声，教出错误的偏好。

## 5. 规模、配比与难度分层

### 5.1 目标规模

| 组       |  占比 | 说明                              |
| ------- | --: | ------------------------------- |
| A 结构规划  | 20% | 其中 A2 占 15%                     |
| B 大纲    | 12% | B2 为主                           |
| C 细纲与自查 | 22% | C1 18% + C2 4%… 见 §3.2.7/§3.3.7 |
| D 正文    | 32% | D2 : D1 = 2.5 : 1               |
| E 选节编辑  |  9% | 四动作均分                           |
| F 负例/修复 |  5% | 另附 DPO 独立文件                     |

**最小可用规模**（单轮 SFT 起步）：SFT 总量 ≥ 12,000 条；DPO ≥ 4,000 对。  
**推荐规模**：SFT 40,000~~60,000 条；DPO 15,000~~20,000 对。

### 5.2 长度分布（正文类必须铺满，**区间由 §11.1 实测决定**）

> +51 实测：单次正文可用上限 ≈ **2000~2500 字**，超过 2600 字 ngram 破 0.05，  
> cap ≥ 4096 直接词级复读崩壞。所以**不存在**「单次 3500 字以上」的正例。

| 长度区间         |     占比 | 用途                             |
| ------------ | -----: | ------------------------------ |
| 600–1200 字   |    25% | 分片下限（实测单片 855~1448 是健康区间）      |
| 1200–2000 字  |    35% | **主力区间**（实测 2112 字 ngram 仍为 0） |
| 2000–2400 字  |    30% | 单片上限（实测这个量级仍不退化）               |
| ~~3500 字以上~~ | **0%** | **已删除**：单次生成在物理上不可用，整章靠分片拼     |

**整章（≥2400 字）样本只能用「分片串行」构造** —— 与线上 D2 主路径同构。

### 5.3 难度分层

- **easy**：单线剧情、3~5 个出场人物、无伏笔、`askChars <= 1200`。
- **medium**：双线交织、5~8 人、含 1 条伏笔、`askChars 1200~2400`。
- **hard**：多线 + 群像、含跨卷长线伏笔、含「提醒章」、`askChars >= 2400`，或**末章禁埋形态**、或**细纲已含字段复制需修正**（C2 专用）。

配比 easy : medium : hard = 3 : 5 : 2。**hard 必须真实存在**（否则模型学不会长程一致性）。

### 5.4 语言

`zh` : `en` = 95 : 5。`en` 仅用于 A/C 组（结构化任务），**不用于 D 组正文**（线上正文一律中文）。

## 6. 质量闸（Quality Gates）

> 全部为**确定性可执行**判据。任一条不过 → 拒绝该样本（进入拒绝采样循环）。

| 闸      | 名称     | 判据                                               | 适用    |
| ------ | ------ | ------------------------------------------------ | ----- |
| **G1** | 格式闸    | `format.kind` 对应解析器返回成功                          | 全部    |
| **G2** | 契约闸    | 字段齐全 + 顺序正确 + `duplicatedFields.isEmpty`         | A/C   |
| **G3** | 复读闸    | `charNgramRepeatRatio <= 0.05` 且 `!isDegenerate` | D/E   |
| **G4** | 长度闸    | 落在 §5.2 区间且 ≥ 任务下限                               | 全部    |
| **G5** | 一致性闸   | 伏笔章号 ∈ [1,total] 且 span ≥ 2；末章无伏笔小节              | C1    |
| **G6** | 去重闸    | 与已有样本的 13-gram Jaccard < 0.7                     | 全部    |
| **G7** | 语言闸    | `cjk_ratio >= 0.85`（`lang=zh` 时）                 | B/D/E |
| **G8** | 教师一致性闸 | 同一 prompt 教师重复 2 次，两次输出在**契约层面**等价（字段集合相同、无互相矛盾） | A/C   |

**闸的失败归因必须记录**（写入 `quality.failed_gate`），用于后续分析「模型哪一类契约最不稳」。

## 7. 生成流水线（用 QWEN3.8-27B 造数据）

```
阶段 0  种子设定库
  ├─ 从项目工艺结构直接产出：题材/背景/主角/群像/起点锚/终点锚/卷数/每卷章数
  ├─ 建议 200~400 个「书种子」，覆盖 12+ 题材
  └─ 每个种子必须自带：totalChapters、锚点对、人物表（≥6 人）、世界观要点

阶段 1  教师生成（QWEN3.8-27B）
  ├─ prompt **逐字**取自 §3 模板（由本仓库的 LayeredPrompts 直接渲染，禁止手写）
  ├─ 教师参数：结构化任务 temperature 0.6 / top_p 0.9；正文任务 temperature 0.85~1.0
  ├─ 每样本独立调用（**不要**用多轮对话累积上下文，否则 prompt 与线上不一致）
  └─ 产出原始 JSONL（保留 attempt 序号，便于拒绝采样统计）

阶段 2  确定性清洗（复用本仓库代码，禁止另写一套）
  ├─ **先剥服务端 `>` 前缀**（§11.7；+51 实测每条 completion 都带，不剥会丢字段）
  ├─ cleanStructured()      → 去开场白/围栏/模板占位/指令回显/`>` 前缀
  ├─ BriefPatch.*           → 细纲解析/重复检测/补丁合并
  ├─ ForeshadowLedger*      → 伏笔解析与结构校验
  ├─ ChapterTitleParser     → 章名可靠性
  └─ RepetitionGuard        → 复读度量

阶段 3  拒绝采样
  ├─ 过 §6 全部闸 → 收录
  ├─ 不过 → 把失败原因回灌进 prompt（追加「⚠ 上一次输出被拒绝：{原因}」）重生成
  └─ 最多 3 次；仍不过则丢弃并计入「该任务族失败率」

阶段 4  负例构造（F 组 + DPO）
  ├─ 对**已通过闸**的正例施加 §4 的确定性变换 → rejected（含 E17 的 `>` 前缀）
  ├─ 同时保留「教师版」与「线上小模型版」的同 prompt 输出作为天然 DPO 对
  └─ 每个 E 码至少 300 对

阶段 5  难度加权与配比采样
  ├─ 按 §5.1/§5.3 采样，避免「easy 淹没 hard」
  └─ 正文类按 §5.2 长度分层采样

阶段 6  切分（防泄漏）
  ├─ **按书切分**：同一本书的所有样本必须落在同一 split
  ├─ train : val : test = 90 : 5 : 5（按书数）
  └─ 禁止按样本随机切分（会造成同书跨 split 泄漏）

阶段 7  打包
  ├─ 写 manifest.json（规模/配比/哈希/模板版本/切分清单/闸通过率）
  ├─ 计算每个文件的 SHA256
  └─ 生成 README.md（含复现命令）
```

### 7.1 教师调用规范

- **单轮**：每次调用只含 `system` + 单条 `user`，与线上 `ChatRequest` 形态一致。
- **不注入思考**：正文与结构化任务都**不要求**教师输出思考过程（线上 `/state` 无视 `think_type`，若训练数据里满是思考，微调后会更爱思考，正文预算被吃光）。
- **可复现**：固定 seed（若教师支持），记录 `teacher_params`。
- **禁手改 prompt**：prompt 一律由代码渲染。人工只允许改**变量取值**（设定、锚点、里程碑）。

## 8. 训练用法

### 8.1 SFT

- **序列化**：`System: {system}\n\nUser: {user}\n\nAssistant: {completion}`（与 `RwkvCloudState.buildPrompt` 同格式）。
- **loss mask**：只对 `Assistant:` 之后的部分计算 loss。
- **stop 序列**：`\n\nUser:`（对应线上 `stop_tokens` 语义）+ EOS。
- **不要**在 completion 末尾补 `\n`（线上解析器会 `trim()`，补了会教出多余换行）。

### 8.2 DPO

- `prompt` 用与 SFT 完全相同的渲染方式（含 `Assistant:` 前缀）。
- `chosen` / `rejected` 必须 `same_prompt`。
- 建议 β = 0.1；先在 SFT 模型上跑 1 个 epoch 观察。

### 8.3 评估（直接用本项目的闸当指标）

| 指标                                        | 目标     |
| ----------------------------------------- | ------ |
| 契约通过率（A/C 组）                              | ≥ 98%  |
| 细纲字段零重复率（C1）                              | ≥ 97%  |
| 伏笔结构零错误率（C1）                              | ≥ 99%  |
| 正文过闸率（D，`>= askChars*0.9` 且 ngram ≤ 0.05） | ≥ 85%  |
| 收尾语出现率（D）                                 | ≤ 1%   |
| 中途断句率（D）                                  | ≤ 5%   |
| 平均 ngram（D）                               | ≤ 0.03 |

> 评估脚本**必须复用** `tools/*_selftest.dart` 的判据实现，避免「训练侧一套、评估侧一套」。

## 9. 验收标准

1. **每族最小样本数**：P0 族 ≥ 800 条；P1 族 ≥ 400 条；P2 族 ≥ 150 条。
2. **自动校验通过率** ≥ 99%（按族分别统计）。
3. **人工抽检**：每族 ≥ 50 条，合格率 ≥ 95%；`hard` 层单独抽检 ≥ 100 条。
4. **负例覆盖**：§4 的 16 个 E 码**每个** ≥ 300 对（SFT 或 DPO）。
5. **无泄漏**：同一 `source.book_id` 不出现在两个 split（脚本断言）。
6. **可复现**：`manifest.json` 记录模板版本 + 教师参数 + 哈希；重跑得到同 split。
7. **训练后回归**：微调模型在本项目 `tools/layered_pipeline_bench.dart` 上的过闸率**不低于**基线（当前基线 5/5、平均 ngram 0.005~0.032）。

## 11. 模型边界能力（决定覆盖区间）· 实测数据

> 由 `tools/rwkv_boundary_probe.dart` 对真机端点实测（2026-10-14，32 次真实调用）。  
> **数据集的可训练长度上限必须落在实测可用区间内**，超出部分只做评估不做训练。  
> 所有正文类探针统一使用**最严防重复采样**（`alpha_decay 0.999` / `freq 0.2` / `dry 0.8` / `top_p 0.6`）。

### 11.1 正文长度边界 ← 最重要的一条

| max_tokens | 实得字数 | finish | 自然收束 |      ngram | 收尾形态（实测样本）                  |
| ---------: | ---: | ------ | ---- | ---------: | --------------------------- |
|        512 |  525 | stop   | ✗    |     0.0000 | 被 max_tokens 截断（「…镇子唯一」）    |
|       1024 | 1054 | stop   | ✗    |     0.0000 | 截断（「…礁石产」）                  |
|       2048 | 2112 | stop   | ✗    |     0.0000 | 截断（「…结构体」）                  |
|       4096 | 2633 | stop   | ✗    | **0.0755** | **复读崩壞（「险峻陡峭危崖绝壁……绝壁」×数十）** |
|       6144 | 6356 | stop   | ✗    | **0.3338** | 复读崩壞（对白循环）                  |
|       8192 | 3170 | stop   | ✗    | **0.1438** | **复读崩壞（「演再次发生类似悲剧重演…」循环）**  |

**三条硬结论**

1. **单次可用上限 ≈ 2000~2500 字。** 超过 ~2600 字 ngram 就突破 0.05 阈值；cap ≥ 4096 时出现**词级复读崩壞**（同一个词反复刷屏）。
2. **不能依赖模型自然收束。** 6/6 全部 `endsClean=false` —— 要么被 max_tokens 砍断，要么模型自己停在半句。所以「末尾必须是完整句」（E9）必须以**质量闸 + 整章重试**兜底，不能指望模型自觉。
3. 首行普遍带 **Markdown 标题污染**（`# 第一章：退潮时分` / `## 一、钟声与脚步声`）→ 必须作为 E 类污染清洗（+51 已确认正文链路会剥）。

**对数据集的硬性规定**

- D 组正文单片长度区间改为 **600~2400 字**（原「3500 字以上」档**删除**）。
- 整章 ≥ 2500 字的目标**不许用单次生成构造**，必须用「多片串行」的方式拼（这正是线上管线的做法，与 §3.4 的 D2 为主完全对齐）。
- `askChars` 上限设为 **2048**；数据集必须含 `askChars ∈ [600, 2048]` 的均匀覆盖。

### 11.2 结构化输出边界

| 请求条数 | JSON 可解析 | 实得条数 | schema 完整率 |    耗时 |
| ---: | -------- | ---: | ---------: | ----: |
|    5 | ✓        |    5 |   **1.00** |  5.5s |
|   10 | ✓        |   10 |   **1.00** |  9.6s |
|   20 | ✓        |   20 |   **1.00** | 18.3s |
|   40 | ✓        |   40 |   **1.00** | 40.3s |

**结论：结构化输出是强项。** 40 条也能 100% 保 schema、不截断、条数精确。  
→ A1/A2 的 `count` 上限可放宽到 **40**，**不需要**在数据集里教「分段多次调用」。  
→ schema 降级成字符串数组（E11）**本轮未复现**（T=0.6 时），但历史上在 temperature 较高时出现过，仍应保留 E11 负例。

### 11.3 上下文边界

|       前文字数 | 服务端 prompt_tokens | 产出字数 | 结果 |
| ---------: | ----------------: | ---: | -- |
|      2,000 |             2,085 |  153 | ✓  |
|      8,000 |             8,085 |  194 | ✓  |
|     16,000 |            16,085 |  142 | ✓  |
|     30,000 |            30,085 |  228 | ✓  |
| **48,000** |        **48,085** |   90 | ✓  |

**结论：输入侧可以很长。** 48,000 字（≈4.8 万 token）照样 200 接受，虽然模型名只写 `ctx25600`。  
⚠ **诚实的保留意见**：本探针只验证「服务端不报错」，**没有**验证模型真的在利用这么长的前文（未做召回验证）。建议后续追加一条「把暗号放在前文第 30,000 字处，看模型能否引用」的探针。

**对数据集的规定**：`tailContext` 上限可设为 8,000 字（够一章四片串行）；`Book/acceptance` 的 `{{sb}}` 可放到 30,000 字以内。

### 11.4 采样边界

| temperature |   字数 |  ngram | 退化 |
| ----------: | ---: | -----: | -- |
|         0.3 | 2486 | 0.0004 | ✗  |
|         0.6 | 2500 | 0.0000 | ✗  |
|         0.8 | 2500 | 0.0012 | ✗  |
|         1.0 | 2480 | 0.0000 | ✗  |
|         1.2 | 2439 | 0.0000 | ✗  |
|         1.5 | 2432 | 0.0000 | ✗  |

**结论：在最严防重复参数下，温度 0.3~1.5 全都几乎零复读。** 也就是说**复读的主因不是温度，而是惩罚参数**（与 +48「只有 `alpha_decay` 是真正有效的旋钮」一致）。  
→ 数据集正例应来自 temperature **0.85~1.0** 的教师输出（保持多样性）。  
→ ⚠ 此表的所有样本都被 `max_tokens 2400` 砍断（`endsClean=false`），所以它证明的是「**短区间内**不退化」，不是「长区间内不退化」—— 长区间见 11.1。

### 11.5 指令遵循边界（含一个重大发现）

| 检查                   | 原始判定 | **剥离服务端 `>` 前缀后** | 说明        |
| -------------------- | ---- | ----------------- | --------- |
| I1 恰好 3 行且以 `- ` 开头  | ✗    | **✓**             | 内容本就正确    |
| I2 JSON 对象且只有 a/b 两键 | ✓    | **✓**             |           |
| I3 禁用某字              | ✓    | **✓**             |           |
| I4 首句固定              | ✗    | **✓**             | 内容本就正确    |
| I5 恰好 5 个汉字          | ✗    | **✗（真失败）**        | 输出的是 2 个字 |
| I6 用 ①②③ 编号          | ✓    | **✓**             |           |
| I7 纯 JSON 数组无围栏      | ✗    | **✓**             | 内容本就正确    |
| I8 不回抄提示词            | ✓    | **✓**             |           |

**结论：指令遵循其实是强项（8 项里 7 项合格），唯一的真实短板是「精确字数控制」。**  
表面上 5/8 是因为一个**服务端行为**把 3 项假性判负 —— 见 11.7。

### 11.6 跨片续写边界

|  片 |   字数 | 片内 ngram | 跨片 ngram | 回抄前文 | 自然收束 |
| -: | ---: | -------: | -------: | ---- | ---- |
|  1 | 1230 |   0.0000 |   0.0000 | ✗    | ✓    |
|  2 | 1448 |   0.0000 |   0.0000 | ✗    | ✗    |
|  3 |  855 |   0.0000 |   0.0017 | ✗    | ✓    |

**结论：D2「分片续写」是健康的** —— 零回抄、跨片复读可忽略。这与线上管线以 D2 为主路径的取舍一致，也是**后训练最该保持不要破坏**的行为（DPO 的 chosen 里必须有足够的 D2 样本，否则会把这套能力练退）。

### 11.7 ⚠ 重大发现：服务端给每条 completion 加 `>` 前缀

**实测**（+51，3 次对照）：

| 请求                 | 原始 content |
| ------------------ | ---------- |
| 只回复一个字：好（无 system） | `>好`       |
| 同上（带 system）       | `>好`       |
| 同上（不带 stop_tokens） | `>好`       |

字节序列固定为 `[62, …]`（0x3E = `>`）。**与 system、stop_tokens、提示词内容全都无关** ⇒ 这是**服务端 chat 模板行为**，不是模型输出。

**危害（已在代码里修掉）**：结构化链路原先只做 `cleanStructured`，而它不剥 `>`，于是 `>标题：《潮声与灯塔》` 会让 `BriefPatch.parseFields` 的 `^标题：` 匹配失败 → **「标题」字段直接丢掉** → 章名退化成「第 N 章」。正文链路走 `AIOutputSanitizer.extractCleanOutput`，其 `_stripLeadingQuoteBlock` 已经剥掉，所以只有分层管线受影响。

**修复**：`LayeredBookGenerationService.cleanStructured` 开头新增 `_stripLeadingQuotePrefix`（只剥**开头连续**的 `>`，不碰正文里合法的引用），并补 9 条回归自检。

**对数据集的规定（新增 E17）**：

| 码       | 名称         | 症状                   | 检测      | 修正          | 构造法         |
| ------- | ---------- | -------------------- | ------- | ----------- | ----------- |
| **E17** | 服务端 `>` 前缀 | `>标题：…`、`>[…]`、`>正文` | `^\s*>` | 剥掉开头连续的 `>` | 对正例每行前置 `>` |

- **流水线必须**：教师产出落盘前先剥 `>`（否则会把这台服务端的模板行为学进模型，而**换服务端就没这个前缀了**，反而制造脆弱性）。
- **DPO 必须**：E17 每码 ≥ 300 对；`rejected` 带前缀，`chosen` 不带。

### 11.8 边界小结 → 数据集合意区间

| 维度     | 实测可用区间                 | 数据集应覆盖                             |
| ------ | ---------------------- | ---------------------------------- |
| 单次正文字数 | **600~2400**           | 600~2400（删掉 >3500 档）               |
| 整章字数   | 分片拼接可达 ~2400×4         | 2400 / 4800 / 7200 三档（**用分片方式构造**） |
| 结构化条数  | 5~40                   | 5 / 10 / 20 / 40 四档                |
| 前文字数   | ≤ 48000（未验证 Attention） | 0 / 400 / 2000 / 8000 四档           |
| 采样温度   | 0.3~1.5 均不退化           | 教师用 0.85~1.0                       |
| 精确字数控制 | **不可靠**                | 需专门练 + 质量闸兜底                       |
| 指令遵循   | 7/8 合格                 | 按 §11.5 的短板加量                      |
| 长文自然收束 | **不可靠**                | 必须练「完整句收尾」                         |

## 12. 一页速查（给生成脚本作者）

1. prompt **逐字**来自代码渲染，禁止手写。
2. completion 必须能被 `format.parser` 吃下。
3. 8 个细纲字段**必须互不重复**（最高频故障）。
4. 伏笔章号必须在 `[1, totalChapters]` 且 `span >= 2`；末章**禁埋**。
5. 正文末字符必须是句末标点；**禁止**收尾语、标题、大纲回抄、开场白。
6. 负例只用**确定性变换**构造，禁止随机扰动。
7. 按**书**切分，不按样本。
8. **先剥服务端 `>` 前缀再落盘**（§11.7：本部署每条 completion 都带，那是模板行为不是模型能力）。
9. 每样本记录 `template_version`，提示词一改就升版本。
10. 闸不过就重生成（≤3 次），再不过就丢弃并统计失败率。
11. 评估脚本复用 `tools/*_selftest.dart` 的判据，不要另写一套。
12. **单次正文不许超过 2400 字**（实测再长就复读崩壞）；整章一律用分片拼。
13. DPO 的 chosen 里 D2（分片续写）样本必须充足 —— 那是线上主路径，别练退。

### 13.1 可执行闸位

| 闸  | 实现                                                      | 说明                                                             |
| -- | ------------------------------------------------------- | -------------------------------------------------------------- |
| G1 | `_tryDecodeArray` / `_tryDecodeObject`                  | 首字符 `[`、末字符 `]`、元素须为对象                                         |

| G4 | 长度闸                                                     | 单片 ≤ **2400 字**（+52 实测上限）；下限 `askChars*0.9`                    |
| G5 | `ForeshadowLedgerBuilder.build` + 显式章号/跨度/末章禁埋          | **必须给账本完整全书章数**，否则会把 `第6章` 误判成「超出全书 1 章」                       |
| G6 | `DatasetDedup`（13-gram Jaccard）                         | 跨样本，单独调用                                                       |

自检覆盖 **45 条断言**：A 组合格样本应通过；B1~B25 每个错误码都应被抓到；  
C 组去重；D 组指标；E 组契约常量与范式一致。

### 13.2 ⚠ 制定范式时真实踩到的三个坑（都靠自检发现）

1. **G7 不能对 JSON 用正文阈值**：一份完全合格的里程碑数组，中文比例只有 **0.40**  
   （`{}[]",` 占掉大半字符），用 0.85 去卡会把合格 JSON 全毙掉。  
   → 改成按格式种类分档：`prose 0.85` / `textLines 0.30` / `json 0.02`。
2. **中文比例必须计入中文标点**：`,。：；、！？「」《》——…` 不算中文的话，  
   真实正文的比例只有 0.83~~0.84，全被卡在 0.85 以下。  
   → `cjkRatio` 纳入 0x3000~~0x303F、0xFF00~~0xFFEF、0x2010~~0x2027。
3. **大纲不是 prose**：`# 卷名` 这类条目化标记在大纲里是**合法**的，  
   用 prose 的 G3 去审会把合法大纲判成 E5。→ 审计时大纲用 `textLines`。
